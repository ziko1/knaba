# Private route and travel view

The internal travel page renders a local interactive SVG geographic sketch from fresh, already server-authorized entity responses. `RouteMapView` receives `records`, localized `copy`/`stateLabel`, locale and optional refresh/site-navigation callbacks. App owns requests, current authentication, revocation handling and route integration. The same-origin landing is `/app/trips?map=1`; coordinates never belong in URL parameters.

The server remains the authority: `Engine.readEntities` filters `location_sample` by current identity, own access or approved GPS-history role and complete site scope; PostgreSQL exposes raw coordinates only before their TTL. The client model never grants permission. It checks exact expiry again, finite numeric coordinates, nonzero sentinel, device/policy reference, BUSINESS_TRAVEL mode, matching authorized trip/employee/shift, trip interval and returned event-time travel segments. Optional returned policy metadata is checked at event time. A missing policy response does not invent an approval or a denial; the existing server-authorized response governs access. Do not pass unfiltered aggregate dumps to this component.

Selected-day filtering uses Europe/Berlin, including midnight and DST. Display is bounded to the latest 1,000 valid points for that day from at most 5,000 supplied samples; a visible limit notice makes truncation explicit. Observation time and receipt time remain separate. A displayed device position is not proof of a person's presence.

The sketch supports zoom, drag pan, keyboard-accessible pan/reset buttons, point selection, trip/day filters and known authorized site focus. Site markers use supplied site coordinates or the site's current authorized geofence version. Addresses without coordinates remain explicitly unknown; no geocoder is called. Optional site navigation receives only an already authorized site ID.

Measured points have chronological lists, accuracy, source/device/policy provenance and uncertainty markers. Trips show actual intervals, origin/destination where authorized, availability and approval separately. Missing sequence/time/quality intervals are flagged. There are no connecting route lines, extrapolated positions, calculated journey distance, predicted arrival times or reconstructed private paths. A historical point never establishes a current tracking state.

Physical activity, presence, tracker status and collection mode remain separate. Missing/stale/non-ONLINE observations produce UNKNOWN presence. Private break and ended shift display PRIVATE_BREAK/OFF; an unobserved or expired/revoked native session remains UNKNOWN. Working time and pay are unaffected. The TTL timer removes displayed/selected points at expiry; authentication refresh must also replace or clear prior responses when current access is denied. HTTP GPS responses must remain private/no-store.

The component uses no external tiles, routing provider, browser geolocation API, service-worker cache, localStorage, IndexedDB or downloadable track persistence. The SVG projection is an approximate geographic sketch with latitude orientation and dateline handling, not a navigation map. Provider navigation, credentials, legal transfer and physical GPS/battery acceptance remain external prerequisites and **NOT_RUN**.

A current hosted 360px screenshot/interaction run and live Railway map acceptance are **NOT_RUN** until their receipts exist. No physical or map-provider result is inferred from these CPU checks.
