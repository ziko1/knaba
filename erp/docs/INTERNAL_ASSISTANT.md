# Internal AI drafts

Spec 8.5 and 9.3 are implemented by `packages/integrations/internal-assistant.ts`, the closed provider contract in `internal-assistant-provider.ts`, `DeepSeekAdapter.proposeInternalDraft` and the API host in `apps/api/internal-assistant.ts`. The registry and worker integration are owned by the API/worker runtime. The provider proposes data; the current human actor authorizes canonical business commands.

## Commands and scope

`internal_assistant.request` requires the caller's current `assistant.read`, `chat.read`, a permitted internal role and the target permission (`task.create`, `report.create` or `inventory.request`). Allowed roles are OWNER, DIRECTOR, OPERATIONS_MANAGER, INTERNAL_BAULEITER and TEAM_LEADER; customer, external Bauleiter and guest roles deny access even when extra permissions are present. Assignment additionally requires `task.assign`.

The strict request is `{messageId,messageVersion,channelId,configId,configVersion,kind,siteIds,context}`. `kind` is TASK_BATCH, REPORT or MATERIAL_REQUEST. `context` contains only explicitly selected arrays `locationIds`, `assigneeIds`, `taskIds`, `materialIds`, `orderIds`, `reportIds`; omitted arrays become empty. Bounds are 10 sites, 100 locations/tasks/materials, 50 assignees and 20 orders/report references. All IDs must be current, company scoped, visible and within selected assigned sites.

The source is the caller's HUMAN message in a current, visible COMPANY_GENERAL, COMPANY_ANNOUNCEMENTS, TEAM, SITE_INTERNAL or TASK_THREAD channel. Direct/private/customer/confidential channels are excluded. Membership expiry, revocation, history access, source author, channel/source/config versions and current site assignments are checked again when preparing, before sending to the provider, when saving the private draft and when reviewing/confirming. A site/task channel cannot select another site. Current paths include every active ancestor with cycle/depth bounds. The provider receives labels/IDs, full selected paths, eligible worker labels/site IDs, task titles/state, catalog material units and order/customer IDs. Salary, bank, stock, prices, unrelated chats and full employee/customer records are excluded.

`internal_assistant.preview` takes `{draftId}` and returns the current owner's private preview with `draftVersion`, `previewHash`, exact source reference and clarification/confirmation status. It must run as a fresh read in Engine. TASK_BATCH previews show complete selected paths, original excerpts, executors, unchecked checklists and acceptance criteria. `internal_assistant.confirm` takes `{draftId,expectedVersion,previewHash,confirmed:true}`. It revalidates current rights, references and the reviewed plan, then invokes the current human's canonical handler within the same transaction:

| Draft | Canonical commands | Result after confirmation |
| --- | --- | --- |
| TASK_BATCH | `task.bulk.preview`, then `task.bulk.commit` | Atomic batch of at most 20 tasks; DRAFT or ASSIGNED; INTERNAL billing and no customer visibility |
| REPORT | `report.create` | DRAFT Leistungsnachweis with approved scoped task references; no legal acceptance or publication |
| MATERIAL_REQUEST | `request.create` | Own DRAFT material request with exact canonical base quantity; no submit, approval, stock movement or purchase |

Whole-batch failures roll back business entities, draft confirmation, receipts, audit and outbox. Same command receipts replay before effects; a later valid confirmation returns the existing draft result without new entities. Existing source/path/permission changes reject a new confirmation.

## Provider boundary and worker lifecycle

`prepareInternalAssistant(companyId,requestId,host)` atomically changes PENDING to RUNNING before provider I/O and returns `{done:false,request,config,contextHash,providerInput}`. Terminal requests return `done:true`; a current RUNNING request cannot automatically start another provider round. `providerInput` intentionally omits `budgetRemainingCents`: the worker must reserve the actual INTERNAL_DRAFT category budget, merge that amount and call the adapter. The current configuration controls model, timeout, tone, Sie/du and human hours.

After reservation, `revalidateInternalAssistant(companyId,requestId,contextHash,host)` checks current RUNNING state, actor/source/channel/config/selected references, exact worker lease and current specific AI_TRANSFER approval immediately before provider I/O. Real personal data remains blocked without a valid external transfer approval and configured provider region; test transfer bypass requires explicit DEMO/TEST plus the current `testOnly` configuration. The adapter independently checks approval configuration and bounded cost.

`persistInternalAssistantDraft(companyId,requestId,contextHash,result,host)` rechecks the same references and exact lease before and after its write, reparses the closed proposal and records READY or NEEDS_CLARIFICATION. Results include `{proposal,provider,model,usage?}`; `usage` uses integer `input_tokens`, `output_tokens`, `cost_cents` for actual reservation settlement. The AI never performs tool execution, creates business entities or authorizes another role.

Unknown provider outcomes retain authoritative status RUNNING and the budget reservation. `markInternalAssistantUnknown(companyId,requestId,reason,host)` records `providerOutcome:UNKNOWN`, typed reason and `unknownAt`, guarded by the current lease. Lease loss also prevents this write; existing RUNNING still holds privacy quiescence. `failInternalAssistant` handles proved pre-provider/terminal failures and cannot turn an explicitly UNKNOWN request into quiescent FAILED. Source access cannot be erased while the provider outcome remains unresolved.

Closed proposals deny extra commands, prices, completed checklists, customer visibility, stock/finance/GPS effects and IDs outside the explicit context. Each task carries an exact original `sourceQuote`. Complete canonical floor tokens must occur in that excerpt; `EG` cannot match “Regal” and `1. OG` cannot match “11. OG”. Colliding floor names additionally require a unique selected path token. Unspecified ordinal/plural locations require clarification. Material quantities and deadline timestamps, report periods and nondefault task quantities require stated source facts. Supported timestamps here are explicit ISO timestamps; relative or unspecified deadlines require clarification. Reports are restricted to Leistungsnachweis; legal acceptance, timesheet and photo-document workflows remain separate canonical commands.

Durable events are `internal_assistant.requested` ({requestId,ownerUserId,category:INTERNAL_DRAFT}), `.draft_prepared` ({requestId,draftId,ownerUserId,kind}), `.failed` ({requestId,ownerUserId,error}), `.outcome_unknown` ({requestId,ownerUserId,error,category}) and `.confirmed` ({requestId,draftId,ownerUserId,command,entityIds}). Requests and drafts store canonical `messageId`, `sourceMessageId`, `channelId`, `ownerUserId`, `user_id` for the privacy graph. Current RUNNING requests hold source/copy/cache components regardless of terminal outbox status. Confirmed drafts and business receipts are retained for legal review rather than erased as private caches.

## Verification and external limits

`tests/internal-assistant.test.ts` executes actual canonical domain handlers in a serialized CPU transaction fixture. `tests/internal-assistant-provider.test.ts` exercises the actual adapter with synthetic HTTP completions. These prove implementation boundaries; they are not real DeepSeek quality, privacy approval, physical or hosted acceptance.

`tests/internal-assistant.integration.test.ts` contains 11 genuine PostgreSQL/Engine transaction, replay, stale source/lease, canonical rollback, owner/privacy scope and actual adapter-to-private-preview tests. It also runs actual WorkerRunner leasing, INTERNAL_DRAFT reservation and settlement, disabled-provider handling, revocation between reservation and provider I/O, changed sources during the provider round and unknown outcomes across failed outbox/retry. External HTTP completions are explicitly synthetic fixtures. With no DATABASE_URL these are skipped and remain NOT_RUN. Run against an isolated QA database with `npx vitest run tests/internal-assistant*.test.ts`; consult `docs/evidence/internal-assistant-offline-result.json` for the exact current offline result. The current offline result is 68 PASSED and 11 PostgreSQL NOT_RUN with typecheck PASSED. Current hosted source acceptance must be independently verified after integration. Real-provider content quality, external DPA/region/legal approval and real company work remain BLOCKED_EXTERNAL until evidenced.
