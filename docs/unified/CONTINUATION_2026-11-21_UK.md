# KNABA DE · план продовження від 21 листопада 2026

Перший результат для користувача — після входу мобільний застосунок відкриває доступний кабінет, пропонує вибір або пояснює відсутність доступу. До вибору застосунок не повинен завантажувати робочі дані. Цей етап охоплює Android та iOS. Далі за залежностями йдуть реальні рольові операції, зв’язок із сайтом та асистентом, приймання й передача. Пріоритети враховують наявний код і відкриті задачі, календарні дати залежать від результатів тестів і доступності обладнання.

## Порядок роботи і бюджет

Вести роботу в наявних memory, roadmap і backlog KNABA. Для першого етапу окремі виконавці працюють із Kotlin і Swift, QA перевіряє інструменти та регресії, рецензент звіряє поведінку з серверними ролями. Ліміт на нові платні сервіси цього етапу — 0 €. Використовувати локальні перевірки й наявні автоматичні перевірки PR. Додаткові витрати, підпис для розповсюдження та зовнішня відправка потребують окремого рішення власника.

Повернення першого етапу — скасувати його окремий commit у гілці PR. Схема й дані ERP не потребують відкату для зміни мобільної навігації. Для етапів із міграціями виконати окрему репетицію на відновленій копії.
