# KNABA DE Test 0.4.2 — іконка та встановлення на Android

Це окремий тестовий APK для **Android 12 або новішого**: пакет `de.knaba.mobile.test`, версія `0.4.2-test`, code `6`. Назва на телефоні — **KNABA Test**. Він зберігає функції 0.4.1 і містить чинний корпоративний знак: три бірюзові будівлі з лаймовою основою.

## Як встановити

1. Завантажте окремий файл **`KNABA-DE-0.4.2-test.apk`** повністю на телефон.
2. Відкрийте системний застосунок **«Файли» → «Завантаження / Downloads»** та натисніть саме цей `.apk`. Якщо відкриття вкладення безпосередньо з ChatGPT нічого не показує, цей шлях допомагає окремо перевірити відкриття вже збереженого файла.
3. Оберіть стандартний **«Інсталятор пакетів»**. Якщо Android попросить, натисніть «Налаштування» й дозвольте встановлення **для застосунку, з якого відкрито файл** — наприклад, «Файли» або браузера. Поверніться до інсталятора й натисніть **«Встановити» / «Оновити»**. Назви пунктів залежать від виробника телефона.
4. Відкрийте **KNABA Test**. На екрані входу можна вибрати демонстраційний режим із синтетичними даними.
5. Після встановлення можна знову вимкнути дозвіл установлення з цього джерела.

Для інсталяції не потрібні сторонній інсталятор, root, режим розробника або вимкнення Play Protect. Не видаляйте попередній застосунок і не очищайте його дані, щоб примусово встановити оновлення. Пакет `de.knaba.mobile` є окремим застосунком; цей тестовий пакет не підміняє його.

## Що перевіряється перед передаванням файла

`scripts/package.sh` перевіряє фактичний скомпільований APK: package/version, криптографічний v2-підпис, вирівнювання ZIP, CRC, цілісність обов'язкових файлів, відсутність `testOnly` і залежних split-пакетів, minimum/target SDK та launcher activity. Для оновлення передається `KNABA_ANDROID_EXPECTED_CERT_SHA256` зі звіреним сертифікатом попереднього APK; невідповідність зупиняє пакування.

Підпис залишається **тестовим Android Debug**, не production-підписом власника. Докази поточного кандидата та точний SHA256 файла: [verification.json](evidence/android-install-icon-20261108/verification.json). Перевірки метаданих, build і Robolectric самі по собі не доводять встановлення на фізичному телефоні.

## Що відомо про повідомлену проблему

Два збережені екземпляри попереднього APK 0.4.1 збіглися байт-в-байт. Їхній ZIP і v2-підпис справні; у binary manifest немає `testOnly`, split-залежностей або обмеження конкретною архітектурою процесора. Отже, за цими файлами **не підтверджено причину** мовчазного закриття стандартного інсталятора на телефоні користувача. Спосіб передавання вкладення, фактичний файл на телефоні, налаштування джерела й повідомлення Android залишаються неперевіреними.

Якщо після кроків вище вікно встановлення все одно не з'являється, надішліть:

- модель телефона і версію Android;
- з якого застосунку відкриваєте файл;
- скриншот або короткий запис від натискання на `.apk` до зникнення інсталятора; якщо є текст помилки — його повністю.

Не надсилайте паролі, токени чи приватні дані компанії. Повідомлення «нічого не відбувається» без цих даних не дозволяє відрізнити проблему передавання файла від відмови інсталяції.

## Межі кандидата

Чинний логотип використаний байт-в-байт із `corporate-site/public/favicon.png`. Adaptive і round ресурси мають білий фон та поля для стандартних масок Android. Зображення не перемальоване.

Встановлення/оновлення на фізичному телефоні та збереження локальних даних потребують окремого підтвердження. Реальний ERP, iOS, GPS і приймання всього продукту не стають перевіреними від зміни іконки. Попередня [інструкція функцій 0.4.1](TEST_ANDROID_0.4.1_UK.md) залишається актуальною для демонстрації та обмежень доступу.

Офіційні джерела: [Android — дозволи встановлення з інших джерел](https://developer.android.com/distribute/marketing-tools/alternative-distribution), [Android — adaptive icons](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive).
