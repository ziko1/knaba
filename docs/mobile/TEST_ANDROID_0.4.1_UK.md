# KNABA Test 0.4.1 — встановлення й перевірка Android

Статус: **тестовий кандидат**, не фінальний клієнтський реліз. Android 12 або новіший. Нативний застосунок, окремий пакет `de.knaba.mobile.test`.

## Встановлення

1. Завантажте `KNABA-0.4.1-test.apk` на телефон. Відкрийте файл і за потреби дозвольте встановлення з цього джерела.
2. Якщо вже встановлено **KNABA Test 0.4.0**, встановлюйте оновлення поверх нього. Версія 0.4.1 має той самий перевірений debug-сертифікат і code 5 замість 4. Реальне оновлення на вашому телефоні ще не перевірене; це не гарантія збереження даних у конкретному пристрої.
3. Не видаляйте попередній застосунок і не очищайте його дані, щоб примусово встановити файл. Якщо Android відхиляє оновлення, збережіть повідомлення про помилку для перевірки.
4. Пакет `de.knaba.mobile` з іншої попередньої збірки залишається окремим застосунком. Ця збірка встановлюється як **KNABA Test**.

## Тест без доступу до компанії

На екрані входу оберіть демонстраційний режим. Дані позначені як тестові й зберігаються лише в пам’яті; вихід або завершення процесу скидає демонстрацію. Вона не надсилає запитів у компанію та не вмикає GPS.

Перевірте головний екран, пошук задач, початок роботи, внесення виконаного обсягу, передавання на перевірку й чат. Перевірте повернення між екранами, поворот телефону та потрібну мову: DE/EN/PL/LT/RU/UK. Нова інсталяція починає з німецької, збережений вибір мови підтримується.

## Що змінилося у 0.4.1

Якщо сервер міг виконати дію, але застосунок не отримав відповідь, він зберігає її початкові дані та ключ повтору в окремому зашифрованому журналі. Після повторного входу **на той самий сервер, у ту саму компанію й обліковий запис** з’являється екран перевірки невідомого результату.

- Повторення виконується лише після вашого натискання й використовує той самий запит.
- Вихід не стирає невирішений запис. Інший обліковий запис не бачить його.
- Якщо після невідомого результату доступ заборонено, застосунок не оголошує стару дію невиконаною. Потрібна перевірка відповідальним оператором.
- Пошкодження локального журналу або неможливість безпечно записати запит блокують відповідну операцію; помилка не підміняється успіхом.
- Виправлено відновлення попереднього AtomicFile-файлу після перерваного запису та перевірку зміненої/некоректної ідентичності сервера.

Журнал не містить пароля входу, сесійного cookie чи CSRF-токена. Його ключ і файл відокремлені від обліку часу/GPS. Відновлення реального незавершеного запиту перевіряйте лише на погодженому тестовому ERP із синтетичними даними. Демонстрація сама по собі цього сценарію не доводить.

## Вхід до справжньої системи

Потрібні перевірена HTTPS-адреса **ERP**, тестовий обліковий запис та належні серверні права. Адреса корпоративного сайту не означає автоматично адресу ERP. Спільний вхід сайт↔ERP ще не прийнятий; не використовуйте реальні клієнтські чи фінансові дані для перевірки кандидата.

Функції часу/GPS залишаються окремим сценарієм із реєстрацією пристрою, дозволами й погодженою політикою компанії. Ця збірка не є дозволом активувати відстеження працівників.
