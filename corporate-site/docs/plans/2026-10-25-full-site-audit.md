# KNABA: аудит і контент будівельного клінінгу

Запит: «повний аудит сайту на всіх сторінках kneba.vsp.rest, перевірити, чого бракує, виправити й максимально наповнити змістом про будівельний клінінг».

Проєкт: ziko1/knaba, development host kneba.vsp.rest. База вихідного коду: `5f4e3d1a8ce100578c90453c7e68bc3f59df91e7`; фактична версія VPS на початку: `7f886606d5711ac93a88d3d93b54a0a9b5638525`. Окрема гілка `feat/knaba-full-site-audit-20261025`. Канонічні memory/roadmap/backlog зберігаються. Нових платних сервісів немає; квоти зовнішніх провайдерів невідомі, dispatch не виконується.

Реалізація використовує наявні компоненти, локальні дані та залежності. Старі CRM service IDs, API, БД та права не змінюються. Вміст доступний у HTML без залежності від відкриття accordion чи виконання JavaScript. Спеціальні технічні роботи залишаються предметом окремого погодження, без вигаданих цін, кваліфікацій, клієнтів чи гарантій.

План перевірок: існуючі typechecks, Vitest/Node, static build verifier; повна HTTP/HTML матриця; браузер 320/390/768/1440, 200% текст, переходи послуга → форма → мова, клавіатура. Реальні звернення компанії не надсилати. Власницький UAT, юридичне погодження, фізичний пристрій та польові CWV не підміняти лабораторними результатами.

Dev rollout можливий лише після review і перевірки актуальної symlink під lock, вільного диска, резервної копії, незмінної схеми, точного артефакту й code-only rollback. Official knaba.de та main не входять до публікації цього завдання.
