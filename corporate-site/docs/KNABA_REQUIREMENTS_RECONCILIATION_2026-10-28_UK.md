## Виконане виправлення R306: відповіді форми під час навігації

Аудит виявив фактичну втрату відповідей: `Inquiry.tsx` мав тільки component signals, а мовні посилання зберігали лише service query. Три тести на **справжніх state/lifecycle handlers компонента** відтворили втрату даних до підключення нового helper.

`src/lib/inquiry-draft.ts` зберігає одну копію відповідей, етапу та вибраної послуги лише в пам'яті поточного document runtime. Немає Local/Session Storage, cookie, URL з персональними даними, нового серверного запису чи виклику провайдера. Відповіді відновлюються дослівно, summary формується мовою поточного інтерфейсу, згода на надсилання не переноситься автоматично. Пряме нове посилання на послугу враховується, а старий query, перенесений мовним перемикачем або history, не скасовує останній вибір користувача.

Непідтверджена спроба надсилання зберігає **точний body та idempotency key** для повтору, навіть після зміни мови. Реальна зміна відповіді скидає попередню спробу. На підтвердженій квитанції пам'ять і listeners очищаються. При SPA переході незавершений fetch скасовується під час cleanup; запізніла відповідь старого компонента не може перезаписати нову чернетку. Скасування fetch не видається за доказ, що сервер нічого не отримав.

Перевірено реалізацію встановленого Astro 7: `preventDefault()` на `astro:before-preparation` запускає document fallback, а не надійно блокує перехід. Тому цей event **не скасовується**. Зберігається звичайна SPA навігація; native `beforeunload` підключається лише поки є чернетка/непідтверджена спроба, у тому числі під час тимчасового відвідування іншої SPA сторінки. Це стандартний browser warning, не гарантія показу на кожному пристрої. Reload/закриття вкладки після підтвердженого виходу все одно очищають transient memory.

Незалежний review спочатку знайшов і домігся виправлення двох lifecycle дефектів: stale service query та неправильного скасування Astro event. Повторний review — **ACCEPT**, без інших concrete blockers. Додано regressions для обох, off-form explicit service link, renewed consent, retry identity та stale response cleanup.

Фінальна focused команда: `npx vitest run tests/inquiry-draft.test.ts tests/inquiry-navigation.test.ts tests/inquiry-construction.test.ts tests/brand-i18n.test.ts tests/social-card-assets.test.ts` — **30/30 PASS, 5 files**. Harness виконує actual component handlers із контрольованими signals/transport, але не є browser rendering або фізичним пристроєм. `git diff --check` — PASS. Source hashes і межі перевірки: `docs/evidence/requirements-followup-20261028/verification.json`.

## Native Worker: виправлення фактично відсутніх HTTP headers

Встановлена primary Wrangler schema підтримує `run_worker_first: true`, однак фактичний native Sites dispatcher обходить цю настройку для наявних static assets. У v8 лише HTML навмисно вбудовано у Worker; чинні `/api/` requests залишаються у початковому застосунку, а non-HTML JS/CSS/PNG та інші static assets платформа продовжує віддавати сама. Вимоги й hosted PASS для application security headers стосуються HTML/API; для non-HTML перевірено статус, MIME та точні байти, але platform headers можуть бути відсутні. Static wrapper застосовує nosniff/referrer/permissions і noindex за замовчуванням; лише явне runtime `KNABA_RELEASE_MODE=official` може дозволити публічну індексацію. Приватні маршрути й помилки отримують глобальні noindex/nofollow; приватні сторінки — `private, no-store`. Успішні/304 `_astro` ресурси зберігають immutable policy, помилки не отримують річного кешування. Потік, status/statusText, HEAD/304/206, Content-Type, Content-Length, ETag та Location зберігаються без читання/переписування тіла.

TDD на попередньому Worker: **24 FAIL / 7 PASS**; final focused suite: **37/37 PASS**. Незалежний reviewer — **ACCEPT** після збереження upstream stricter robots restrictions і коректного відокремлення agent-scoped directives від глобальних. Враховано також failure caching та GET/HEAD MIME fallback. Receipt і точні SHA/logs: `docs/evidence/requirements-followup-20261028/static-headers-source.json`.

Координатор замінив застарілий build-verifier виклик `.includes()` для масиву на strict `assert.equal(run_worker_first, true)`, зберігаючи сильніший контракт конфігурації Worker-first для всіх requests; його фактичне виконання платформою перевіряється окремо. Обидва verify:build після цього PASS. Історичний v7 readback усе одно виявив, що native dispatcher обходить Worker для фізично наявних HTML. Після окремого artifact finalizer фінальний v8 hosted receipt підтвердив реальні HTTP noindex та private no-store; source checkpoint сам по собі не видавався за live PASS.
