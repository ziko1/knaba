# KNABA — корпоративний органічний трафік і контент (26.10.2026)

## Призначення і межі

SEO-розвиток корпоративного сайту KnaBa, а не блогу, форуму, каталогу сторонніх компаній чи генератора SEO-doorway сторінок. Комерційне ядро: Baureinigung, Bauzwischenreinigung, Baufeinreinigung, Bauendreinigung, Baustellenberäumung, Bauhelfer/Bauhilfe, Baustellenvorbereitung в Berlin & Brandenburg. Технічні Sonderleistungen (Kernbohrungen, Durchbrüche) — тільки запити на оцінку без обіцянок виконання, ліцензій чи дозволів.

**Джерела правди:** чинний corporate-site (активний каталог і маршрути), knaba.de (достовірні реквізити та підтверджені послуги), AGENTS.md, PROJECT_MEMORY.md, roadmap, CRM/Studio. Офіційний сайт описує і ширшу історичну пропозицію, але поточний публічний каталог застосунку навмисно обмежений будівельними роботами: не активувати застарілі Unterhaltsreinigung, Büroreinigung, Treppenreinigung без власника. Старі legacy-маршрути є noindex.

## Точковий реалізований інкремент

- src/data/project-intents.json: чотири реальні сценарії вибору послуги × чотири локалі. Кожен містить ситуацію, корисне пояснення, дані для звернення і точний наявний service slug.
- src/components/ProjectIntentGuide.astro: семантичний, компактний, адаптивний блок для каталогу без клієнтського JavaScript, фальшивих відгуків, рейтингів і цін.
- src/components/ConstructionCatalog.astro: інтеграція одного нового блоку після поточного каталогу та перед фінальним CTA. Чинні послуги, сторінки, CRM, Studio, помічник і форми не переписувалися.
- tests/project-intents.test.ts: контрактний регресійний тест локалей, slug і неактуального офісного клінінгу.

Ця нотатка **не підтверджує** PASS Node24/build/browser/live QA для зміненого SHA. Відповідні тести виконати окремо в середовищі із сумісним Node24.

## Корпоративний стандарт змісту й UX

1. Один змістовний H1, унікальні title/description, H2/H3 для предметних питань. Природна німецька замість переліків ключових слів або штучної щільності.
2. Кожна комерційна сторінка допомагає обрати послугу, пояснює обсяг/винятки, підготовку, відмінності від суміжних робіт і наступний крок через контакт чи планувальник.
3. Публікувати лише правдиві кейси та відгуки з належними правами. Не генерувати вигадані «відгуки клієнтів», рейтинги, сертифікати, партнерства, фото нібито виконаних робіт.
4. Там, де ціна залежить від об'єкта, пояснювати чинники оцінки (площа, матеріали, ступінь забруднення, доступ, терміни, фаза); не вигадувати тарифи, гарантії, вільні дати чи цілодобові послуги.
5. Утримувати сайт компактним: посадкові сторінки конкретних послуг та B2B-галузей, а не новинна стрічка, форум, районні doorway-сторінки чи сотні статей без бізнесової користі.
6. Використовувати справжні семантичні HTML-посилання на актуальні послуги. Не дублювати CTA, зберігати правило одного клікабельного tel: на сторінку та доступність клавіатури.
7. Не погіршувати швидкість: HTML на Astro, мінімум JS, перевірений responsive, contrast, focus, 320/390/768/1440 px, keyboard, zoom/screen reader. Без браузерних доказів — статус BLOCKED, не PASS.
8. Зберігати canonical, hreflang, sitemap, robots і достовірні LocalBusiness/Service structured data. Режим preview/noindex не знімати автоматично.
9. Вимірювати через авторизовані Search Console/Bing Webmaster Tools на погодженому домені: індексацію, покази, запити, CTR, посадкові сторінки; за погодженими правилами приватності — кваліфіковані B2B-звернення з органіки. Жодних вигаданих цифр чи прогнозів.

## Пріоритетні наступні перевірки та розвиток

**P0 — source QA:** Node24 npm run check, npm test, npm run build, npm run verify:build, npm run i18n:verify, test:vps; узгоджений браузерний QA сторінок і форм 320/390/768/1440; незалежний diff/security review, доказ на exact SHA, draft PR. Ніякого main merge або production deployment.

**P0 — реальна компанія:** перед індексацією й живим релізом власник має підтвердити поточний перелік послуг, фото/відгуки/партнерів, реквізити, юридичні сторінки, робочу доставку заявок і домен. Непідтверджені послуги, технічні ліцензії та правові заяви лишаються непублічними.

**P1 — живі корпоративні кейси:** додати 2–3 справжні анонімізовані випадки з фото лише після дозволу: тип об'єкта, задача, погоджений обсяг, виконане, результат. Розміщувати як короткі приклади на комерційних сторінках/портфоліо, а не як блог.

**P1 — conversion measurement:** перевірити шлях organic landing → commercial service → qualified lead, відповідність consent/privacy і роботу CRM/планувальника. Мета — не максимум переглядів, а більше доречних звернень.

**P2 — дані замість здогадів:** за реальними даними Search Console точково покращувати заголовки, відповіді й внутрішні посилання сторінок із попитом, без дублювання існуючих матеріалів.

Документувати SHA, приріст, тести, blockers, відкат. Зміни — окремим Draft PR поверх останнього перевіреного інтеграційного кандидата KNABA; після зміни бази повторно перевіряти exact artifact.
