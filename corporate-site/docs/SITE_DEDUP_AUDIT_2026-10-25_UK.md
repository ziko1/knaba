4. **Візуальна відповідність:** картка планувальника перестає займати окремий широкий ряд, оформлена в тій самій пастельній системі кольорів, що й інші плитки; прибрано повторні CSS-overrides після старого PR.

Вказана лише поточна доменна адреса відповідно до режиму збірки. Юридичні реквізити, телефон, mailto, необхідні політики сторонніх процесорів і внутрішні посилання збережені.
7. **SEO Schema.org:** `LocalBusiness.url/@id`, `Article.publisher` та `Service.provider` прив'язано до `siteConfig.origin`, як і canonical. У режимі `vsp` це власна сторінка шаблону, у погодженому майбутньому режимі `official` — офіційний домен. Не змінено налаштування релізного режиму.

## Запобігання регресіям
- Тести перевіряють одну спільну нумерацію/маршрути шести карток в обох видах і всіх чотирьох локалях (вісім сторінок), із перевіркою унікальності CTA.
- `npm run verify:build` запускає загальний верифікатор усіх HTML і додаткову перевірку карток.
- Загальний HTML-верифікатор відхиляє клікабельні переходи на початковий офіційний домен, дубльовані блоки головних сторінок і JSON-LD, що посилається на іншу бізнес-сутність/домен.
- Зовнішні політики Cloudflare та юридичних регуляторів навмисне не прибрано: ці посилання потрібні для прозорості. `mailto:kontakt@knaba.de` — контакт компанії, не HTTP-перехід на попередній сайт.
- `company.source` і `siteConfig.officialOrigin` залишено як **внутрішню provenance/режим офіційного релізу**, а не рекламні посилання.

cd corporate-site
npm ci
npm run check
npm test
npm run build
npm run verify:build
node tests/design-seo-browser.cjs
node tests/accessibility-reflow-browser.cjs

Після build необхідна ручна/браузерна перевірка DE/EN/UK/RU, 320/390/768/1440px, клавіатури, фокусу, footer, слайдера, FAQ, Studio, логіну та відправлення запиту. За відсутності доступу до live VPS/Opera не ставити **PASS** для цих перевірок. Кодова/структурна перевірка не є підтвердженням реального релізу.
