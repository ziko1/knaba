# KNABA — галерея як робочий процес; референси лише з доказами

**Проєкт:** `ziko1/knaba`, чинна сторінка `/galerie/` у 4 публічних локалях (DE, EN, UK, RU). База для змін: Draft PR #85, `2164b9505f824486594b2633a05f5fd91aee8c04`.

## Рішення для чинної версії

URL `/galerie/` зберігаємо для посилань і SEO. В інтерфейсі називаємо його «Arbeitsabläufe / How we work / Як ми працюємо / Как мы работаем», а не портфоліо або «Наші завершені проєкти».

Тут **чотири схематичні ілюстрації, не фотографії реальних замовлень**. Кожна картка відповідає вже існуючій фактичній послузі KNABA, з окремим конкретним посиланням:
1. Етапи будівельного прибирання → `bauleistungen/baureinigung/`.
2. Підготовка будмайданчика / Bauhelfer → `bauleistungen/bauhilfe/`.
3. Міжетапне прибирання пилу та поверхонь → `bauleistungen/bauzwischenreinigung/`.
4. Фінальна підготовка до здачі → `bauleistungen/bauendreinigung/`.

Використовуємо одну фінальну заявку на сторінку. Не додаємо ще один номер телефону на кожну картку: глобальний Layout уже має одну контекстну контактну точку.

## Коли можна публікувати справжні фото KNABA

Тільки після підтвердження власником компанії джерела й права на публікацію конкретних фото з офіційного KNABA / від замовника. Те, що старий `knaba.de/galerie` показує зображення, **саме по собі не доводить** ліцензію, згоду людей у кадрі чи авторство фотографа.

Один перевірений об'єкт/кейс має містити:
- Послуга з існуючого каталогу (канонічний `serviceSlug`), конкретні виконані етапи та фактичний результат без вигаданих відсотків.
- Стислий заголовок і пояснення DE/EN/UK/RU, перевірені людиною; без автоматичної публікації 95 ще неготових локалей.
- Фото «до/після» лише якщо вони справді з одного об'єкта та узгоджені з правовласником; правильна послідовність і однаковий масштаб/ракурс, де можливо.
- Місце — лише публічно погоджене («Berlin», «Brandenburg» тощо), без точної адреси приватного замовника; дата необов'язкова.
- Доказ прав на використання фото, згода на публікацію впізнаваних людей/логотипів, джерело оригіналу та рішення власника. Підтверджувальні документи **приватні**, не у GitHub чи вебсховищі.
- Оптимізований локальний WebP/AVIF/JPEG, перевірений MIME/розмір, правильний EXIF/privacy removal за потреби; `alt` про фактичну роботу, розміри для стабільного макета.
- Статуси `draft → internal-review → approved → published`. Жодної автоматичної публікації, якщо бракує прав, факту виконання чи підтвердженого джерела.

**Не створюємо** вигаданих кейсів, фальшивих відгуків, AI-картинок «до/після», не копіюємо чужі портфоліо. Реальні кейси згодом використовують **існуючий** Studio/власницький workflow (після доказової перевірки відповідних можливостей), а не нову дубльовану CMS.

## Acceptance gates

- Існуючий маршрут і 4 локалі працюють, 4 процеси = 4 відповідні внутрішні URL, тільки один контактний CTA і один `tel:` на сторінку.
- Жодних тверджень, ніби схематичні ілюстрації — реальні завершені об'єкти.
- Node24: `npm run check`, `npm test`, `npm run build`, `npm run i18n:extract` + `i18n:verify`, `verify:build`, `test:vps`.
- Повний HTTP smoke всіх створених сторінок у одноразовому ізольованому QA (рекламні/переадресовані legacy URL враховуємо окремо).
- Живий публічний preview тільки після exact-SHA QA, backup SQLite, захищеної операції перемикання і rollback. `knaba.de` та `main` не змінюються без окремого релізного допуску.
- Реальне візуальне / мобільне QA позначається `NOT_RUN` якщо Opera/Playwright не доступні; статичний PASS не замінює browser PASS.

## Джерела рішень

- Офіційні KNABA: `https://knaba.de/galerie`, `https://knaba.de/leistungen` — джерела для порівняння номенклатури, але не дозвіл на копіювання зображень.
- Nielsen Norman Group, «What B2B Designers Can Learn from B2C About Building Trust» — докази використання реальних прикладів, змістовної інформації та прозорості B2B сервісів.
- Nielsen Norman Group, «Photos as Web Content» — релевантні фотографії допомагають користувачам більше за декоративні зображення.
