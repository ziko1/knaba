# Перевірка SSH setup

Дата: 2026-10-28.

## Результати

| Перевірка | Результат |
| --- | --- |
| `bash -n ssh.sh` | PASS — синтаксис Bash |
| `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s ssh-setup/tests -v` | PASS — 22 ізольовані тести |
| Незалежний перегляд скрипта | Конкретних блокерів безпеки або втрати доступу в документованому обсязі не виявлено |
| Встановлення на реальному Ubuntu/Debian сервері | NOT_RUN — доступу до цільового сервера не було |
| Зовнішнє SSH-підключення з Android | NOT_RUN — залежить від сервера, облікового запису та мережевого доступу |

Тести запускаються з тимчасовими файлами та підмінами `sshd`, `systemctl`, `apt-get`, `ssh-keygen` і мережевих операцій. Реальні системні служби, пакети, ключі або правила firewall під час перевірки не змінювалися.

## Що покрито

- Режим `--check` без записів, встановлення пакетів, генерації ключів і зміни служб.
- Збереження наявної конфігурації; створення відсутньої зі штатного шаблону; захист пошкодженого символічного посилання.
- Зупинка до активації за помилки конфігурації, нестандартних параметрів служби, помилки systemd або `masked`.
- Встановлення відсутнього SSH-сервера; виявлення невідповідності між бінарником і службою.
- Збереження режиму socket activation та повторний запуск без переписування конфігурації чи генерації ключів.
- Запуск через файл та `bash -c`, правильне передавання `--check` як позиційного аргументу.
- Помилка завантаження навіть із частковим тілом не запускає код; помилка виконаного скрипта зберігає ненульовий код завершення.

Ці результати підтверджують перевірені сценарії скрипта. Вони не є підтвердженням доступності SSH на будь-якому зовнішньому сервері.
